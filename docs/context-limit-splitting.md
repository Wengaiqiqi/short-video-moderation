# Jev 图片上下文超限自动拆分

桌面审核、失败片段重试和命令行审核都使用 `providers.evaluate`。
当 Jev 返回 HTTP 400，且结构化错误码明确为 `max_tokens_exceeded` 时，
将该片段的图片列表按原时间顺序二等分，再请求两半；仍超限则继续二分。
所有图片保持原字节与时间戳，各成功子批次合起来覆盖原全部图片。

每个子批次保留原片段起止时间、完整语音及前后语音上下文。
子批次按类别取最高分合并，沿用原有风险聚合方式；阈值不变。
拆分会减少同一请求中可共同看到的画面，属于请求适配策略变化，评测报告应标明。

子请求在原有共享并发槽内顺序执行，不额外扩大并发；每个子请求有新的幂等键。
成功子请求的 usage 相加，服务端未返回的失败调用用量不作估算。
原生报告的 `context_split` 包含拒绝批次、成功子批次的时间戳、分数、模型与用量。

其他 HTTP 400、权限或认证错误不会触发拆分。纯文本请求不按图片拆分。
若单张图片仍超限，保留 `max_tokens_exceeded` 错误；任一子批次失败，
整片段保持失败，不把部分成功的结果当作完整审核。已成功子批次仍记录用于追踪。
原有 OpenAI 对照适配器保持其错误处理行为。
